# 0.8.2：屏保照片扫码上传

2026-10-25，部署于MiTV4-ANSM0、Android6.0.1／API23。入口为“桌面设置 → 本地图片屏保 → 图片管理与导入 → 电脑 / 手机传图”。

## 交互与实现

- 电视显示大幅二维码，旁边保留手动地址、六位连接码和已保存张数。手机在同一局域网扫码后进入上传页，连接码自动填入；用户选择照片并点“保存到电视屏保”。
- 地址使用当前接收器实际绑定的IPv4和端口，兼容默认端口被占用时的临时端口；不写死某一台电视的IP。连接码放URL片段，浏览器读取后从当前地址栏清除，不通过GET查询参数发送。POST仍须提交正确连接码，没有绕过原有校验。
- 网页同时处理初次加载和`hashchange`，手机复用已打开的页面再次扫码时也会更新连接码；六位码的前导零保留。没有二维码或片段无效时保留手动输入方式。
- 二维码使用Nayuki v1.8.0的MIT编码库，在电视上本地生成；整数像素绘制黑白模块，保留四模块静区，不调用外部二维码服务，也不申请相机权限。来源、哈希与许可见根目录第三方说明。
- 上传成功仅更新张数，二维码及地址保持显示。完成传图、返回关闭或离开图片页会关闭监听及活动连接。重新打开时生成新的本次连接码。原有单图32MB、最多24张、错误码与尝试次数限制保持。

## 验证结果

- 219项Java断言通过，包含25项上传服务断言，覆盖真实监听地址／端口和二维码链接、正确／错误码、限额、坏图、连接关闭等；API23扫描1522项成员引用，APK v1/v2/v3验签通过。
- 对电视实机截图使用独立二维码解码器，成功取得完整上传链接；没有用编码库自身作为解码校验。上传后再次解码，地址与连接码保持一致。
- 真实浏览器打开解出的链接，自动填码并清除片段；选择本地生成的测试PNG，最终版本实际返回保存成功，电视张数同步增加。390×844浏览器视口没有横向溢出，上传按钮可用。
- 复现并修复同页再次扫码不填码的问题；最终版本已验证无效片段不填码、同页有效片段更新、前导零保留和正常上传。另一次会话已核对旧连接码被拒绝。
- 关闭传图窗口以及离开图片页后，端口不再接受连接。验收中仅移除明确标记的测试图片，用户原有照片保留；最终回到新桌面，未开启常驻上传服务。
- Home三次2.16／2.11／2.08秒。本轮没有完整重启或重复完整屏保轮播、USB插拔及有信号HDMI测试。扫码验证使用实机截图的软件解码及真实浏览器，没有声明所有手机相机、微信内置浏览器均已逐机验收。
